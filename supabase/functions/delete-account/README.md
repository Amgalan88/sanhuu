# delete-account

Нэвтэрсэн хэрэглэгч өөрийн дансыг устгана. Клиент `Бусад` цэсний «Данс устгах» товчоор дуудна.

Энэ функцийг **байршуулаагүй**. Прод (`evtawdwjlwniwjjimkfh`) руу энэ файлаас автоматаар очихгүй.

## Юу хийх вэ

1. Хүсэлтийн `Authorization: Bearer` JWT-г `auth.getUser` дээр шалгана. Токенгүй, хуурамч токенд данс устгахгүй.
2. Хэрэглэгчийг өрхөөс нь хасна.
3. Тэр хүн өрхийн **сүүлийн** гишүүн бол өрхийн орлого, зарлага, шилжүүлэг, зорилтын шилжүүлэг, аудит, амжилт, чат, урилга, гишүүд, өрх өөрөө устана. Зургийг `achievements` bucket-ээс хасна.
4. Өөр гишүүн үлдвэл өрхийн мөнгөн мэдээлэл үлдэнэ. Зөвхөн энэ хүний гишүүнчлэл, профайл зураг явна.
5. Дараа нь Supabase Auth хэрэглэгчийг устгана. Зөвшөөрлийн мөр `consents` хүснэгтээс хамт явна.

Өөр гишүүн үлдэхэд хамтын мөрийн `created_by` хоосорч болно. Үүний тулд `supabase/migrations/20261123153000_legal_consents.sql` доторх `ON DELETE SET NULL` хэрэгтэй. Миграцигүйгээр Auth устгал гаднын түлхүүр дээр зогсоно.

## Эзэн зөвшөөрсний дараа

Хуучин миграцийг (`baseline` дахь `DELETE` орсон файл) дахин бүү ажиллуул. Зөвхөн энэ шинэ файлыг SQL Editor дээр ажиллуулна.

1. Dashboard → SQL Editor → `supabase/migrations/20261123153000_legal_consents.sql` бүхлээр нь.
2. Функц:

```bash
npx supabase functions deploy delete-account --project-ref evtawdwjlwniwjjimkfh
```

`--no-verify-jwt` бүү нэм. Шинэ нууц түлхүүр хэрэггүй. `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`-г платформ өөрөө өгнө.

`db push` нь энэ функцийг байршуулахгүй. Мөн хүлээгдэж буй өөр миграци хамт явж болзошгүй тул прод дээр сохор `db push` бүү хий.
